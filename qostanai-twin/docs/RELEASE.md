# Комплект для демонстрации 0.12.0

Интерфейс — 0.12.0, серверный контракт — 0.8.0. Добавлен [ИИ-агент](AI_AGENT.md) с инструментами чтения данных и сравнения сценариев. Требуется перезапуск старого сервера. Тестовые данные и помощник на правилах остаются в [разделе кейса](CASE_DATA.md). Инструкция для нового ноутбука — [START_HERE.txt](START_HERE.txt).

## Проверка в приложении

В разделе «Показ» кнопка «Проверить готовность» выполняет четыре GET-запроса: OpenAPI, снимок модели, список импортов и учебный CSV. Команды модели не отправляются. Шесть результатов показывают версию сервера, связь, поддержку настроек, исходное состояние показа, наличие истории и доступность CSV. Отдельная ошибка не скрывает остальные результаты.

Проверка CSV подтверждает доступность файла, заголовок и ограничение размера; полная проверка строк выполняется при импорте. Пустая история на новом ноутбуке — предупреждение с инструкцией. Подготовка сценария выполняется отдельно кнопкой «Начать учебный показ»: она создаёт новый запуск, сохраняя прежний в архиве.

Смена runId или revision делает результат проверки устаревшим. JSON-экспорт содержит время, версию интерфейса, проверенный runId/revision и результаты. Это технический отчёт на конкретный момент, а не подтверждение качества изображения на проекторе.

## Проверка без браузера

Из папки приложения:

```powershell
.\check.cmd
.\check.cmd --no-pause
.\.venv\Scripts\python.exe -m scripts.runtime_check check --json
```

Проверяются Python ≥3.11, точные версии из requirements.txt, основные файлы приложения, ссылки на ресурсы dist/index.html и совпадение версии сборки с package.json. Локальный порт проверяется чтением API без внешнего прокси. Для актуального API также сравнивается HTML, который сервер отдаёт браузеру, с локальным dist/index.html: это выявляет другую сборку интерфейса даже при той же версии API.

Коды завершения check: `0` — всё пройдено, `1` — ошибка, `2` — предупреждение (например, сервер ещё не запущен или работает прежняя версия). Перед первым запуском отсутствие сервера ожидаемо. Если зависимости отсутствуют или их версии различаются, выполните setup.cmd.

start.cmd проверяет комплект перед запуском. При свободном порте запускается один процесс Uvicorn на 127.0.0.1:4173. При актуальном сервере предлагается использовать его; при старом сервере или неизвестном процессе запуск прекращается с объяснением. Процессы автоматически не останавливаются. Остановка сервера вручную — Ctrl+C в его окне. Проверка не исключает редкую гонку, если другой процесс займёт порт сразу после неё: в этом случае Uvicorn сообщит ошибку запуска.

## Сборка и проверка ZIP

Готовый ZIP содержит папку qostanai-twin, соседнюю pitch-oct09 с существующей презентацией v3, START-HERE.txt и MANIFEST.json. Внутри есть dist, исходники, тесты и примеры. Python, .venv, node_modules, рабочая data и скрытые служебные файлы не включены. Примеры симуляции и эталонные тесты синтетические; src/case-dataset.json содержит переданный пользователем тестовый набор кейса с хешем исходного DOCX. Первая установка зависимостей на новом ноутбуке требует интернета; это не комплект с переносимым Python.

Из папки исходного приложения, где рядом есть pitch-oct09:

```powershell
npm.cmd ci
npm.cmd run build
.\.venv\Scripts\python.exe -m scripts.package_release
.\.venv\Scripts\python.exe -m scripts.package_release --verify ..\zauyt-ai-v0.12.0-demo.zip
```

Можно явно задать `--pitch` и `--output`. Уже существующий ZIP не перезаписывается. Упаковщик отклоняет несовпадающую версию dist, добавляет размеры и SHA-256 каждого файла и проверяет архив после создания. Манифест обнаруживает повреждение файлов; он не является цифровой подписью издателя.

Перед отбором 9 октября установите зависимости и пройдите сценарий именно на ноутбуке для защиты. Проверьте запуск без интернета, презентацию и проектор; сохраните резервное видео. Результаты автоматических проверок и их ограничения — [VERIFICATION.md](VERIFICATION.md).
