# ИИ-агент Qostanai Twin

Раздел `http://127.0.0.1:4173/#agent` принимает вопросы на русском. Сервер передаёт модели описание доступных инструментов, выполняет выбранные расчёты и возвращает ответ вместе с основаниями. Агент не управляет линией: запуск, остановка, восстановление и изменение нормативов остаются отдельными действиями пользователя.

## Подключение

1. Установите и запустите приложение по README. Нужен сервер 0.8.0; если старая копия уже работает, остановите её через Ctrl+C и снова запустите `start.cmd`.
2. Рядом с `package.json` скопируйте `.env.example` в `.env`. Если `.env` уже существует, отредактируйте его, сохранив остальные настройки.
3. Запишите свой ключ в `OPENAI_API_KEY=`. Модель по умолчанию — `gpt-5.4-mini`, её можно изменить через `OPENAI_MODEL`. Требуется модель с Responses API и вызовами функций. В API-проекте должны быть доступ к модели и средства для запросов.
4. Откройте «ИИ-агент» и нажмите «Проверить подключение». Надпись «ключ настроен» подтверждает наличие настройки; доступ к провайдеру проверяется при первом вопросе. `.env` перечитывается при запросах, поэтому после изменения ключа перезапуск не нужен.
5. Выберите «Показатели производства», дату 02.10.2026 и спросите: «Где превышен лимит брака?». Откройте «Основания ответа» и сверьте окраску: 6 / 116 × 100 = 5,17%, лимит 2%.

Ключ хранится на сервере, не в React и не в чате. `.env` исключён из Git и демо-архива. Переменные окружения имеют приоритет над `.env`; файл читается как обычный текст UTF-8 без выполнения команд. Приложение не сохраняет переписку в SQLite: история находится в памяти вкладки и очищается при перезагрузке или смене источника.

## Инструменты

| Источник | Инструмент | Результат |
|---|---|---|
| Тестовый DOCX | `get_case_metrics` | План/факт, доля брака и изменение относительно предыдущей доступной даты; месячный план 4800 при цели 5500 |
| Тестовый DOCX | `get_case_downtime` | Записи простоев выбранной даты с указанными в документе ограничениями |
| Учебная линия | `get_twin_snapshot` | Согласованный снимок постов, буферов, выпуска, событий и модельного прогноза |
| Учебная линия | `compare_recovery` | Сравнение восстановления P01–P05 сейчас и через 0–240 минут на копии снимка |

Источник выбирается до отправки вопроса. Инструменты другого источника в запрос не включаются. Снимок линии фиксируется один раз на вопрос; если линия изменилась, ответ отмечается как устаревший. Сравнение не записывает новое состояние в базу.

Примеры: «Что проверить первым по выбранной дате?», «Почему планы 4800 и 5500 не совпадают?», «Можно ли вычислить OEE?». Для учебной линии: «Какие инциденты требуют внимания?» или «Сравни восстановление P03 сейчас и через 30 минут». Числовой контроль сценария 39 / 421 / 394 описан в [DEMO_GUIDE.md](DEMO_GUIDE.md) и требует указанной там подготовки линии.

## Обмен с моделью и ограничения

Реализация использует [OpenAI Responses API с вызовами функций](https://developers.openai.com/api/docs/guides/function-calling). В OpenAI отправляются вопрос, до четырёх предыдущих пар сообщений и результаты выбранных инструментов. Перед вопросом это указано в интерфейсе. Используется `store: false`; это настройка API, а не обещание отсутствия любых журналов на стороне провайдера.

На вопрос разрешены максимум четыре обращения к модели и шесть вызовов инструментов. Ограничения сервера: два одновременных вопроса, 12 вопросов за минуту, 85 секунд на весь разбор. Один ответ может потребовать несколько платных обращений. Автоматических повторов после ошибки нет. Лимиты действуют на один процесс; запуск предполагает `--workers 1`.

Схемы инструментов строгие, аргументы повторно проверяются сервером. Произвольные функции, команды оборудования, SQL, выполнение кода и доступ к файлам модели не предоставляются. Необработанные ошибки провайдера и ключ не возвращаются браузеру. Наличие вызванного инструмента ещё не гарантирует правильную интерпретацию моделью: выводы нужно сверять с раскрываемыми данными.

Это аналитический LLM-агент, а не обученный предиктор поломок. В кейсе две даты и четыре события: этого недостаточно для оценки точности прогноза. OEE неизвестен, причины брака не указаны, суммировать выпуск последовательных участков нельзя. Без ключа или при недоступности OpenAI остаются локальные расчёты в «Показателях» и «Сценариях».

Приложение рассчитано на локальный показ. В нём нет авторизации пользователей для публичного сервера. Публикация репозитория не запускает FastAPI на GitHub Pages.

## Проверка

Для проверки семи реальных ответов используйте [сценарий оценки агента](AGENT_EVALUATION.md). По умолчанию скрипт проверяет только эталоны; обращения к модели включаются отдельным флагом `--live`.

`backend/test_agent.py` проверяет цикл вызовов с подставным провайдером, исходные числа, неизменность линии, согласованность снимка, ограничения, ошибки доступа, неверные функции и параметры. `tests/agent-source.test.ts` проверяет контракт браузера, контекст ответа и отсутствие автоматических повторов. Эти проверки не используют настоящий ключ и не тратят API-бюджет. 6 октября проверен один настоящий ответ OpenAI по качеству окраски; [результат и ограничения](VERIFICATION.md). Остальные шесть контрольных вопросов ещё требуют реального прогона. На новом компьютере нужен собственный ключ в .env.
