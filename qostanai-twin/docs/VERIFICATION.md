Дата: 3 октября 2026 года.

- 29 TypeScript-тестов прошли, включая 5 новых проверок формы, конфигурации, воспроизводимого сброса, точного повторения команды после сетевой ошибки и соответствия ответа отправленным параметрам.
- 42 Python-теста прошли, включая 8 новых: сохранение разных конфигураций в архиве, восстановление после перезапуска, идемпотентность создания сценария, строгие границы параметров, конфликт вкладок и commandId, отказ записи, сохранение количества изделий на границах диапазона и неизменность CSV-метода.
- Production-сборка и проверка TypeScript прошли. После исправления сравнения объектов с разным порядком ключей повторно прошли 5 относящихся к нему тестов и сборка.
- Контрольная конфигурация (план 275, подача 80 с, циклы 45/60/95/40/65 с, буферы 2/3/4/5) даёт 25 годных на 08:45, прогноз 288, отклонение +13, ограничение P03.

Перед обновлением процесса создана резервная копия SQLite через штатный backup API; integrity_check = ok. Текущий runId и revision перед обновлением: abbd5294-fead-41a8-8519-af040f15224f, 2520; модель на паузе. Автоматическая проверка среды отклонила команду остановки/перезапуска процесса, поэтому обновление работающего API ожидает ручного перезапуска пользователем. Новая команда проверена через FastAPI TestClient на отдельных временных базах; рабочая база для этих тестов не изменялась.

Визуальная проверка формы недоступна: браузерный инструмент возвращает `failed to write kernel assets`, системный путь не найден. Нельзя считать проверенными взаимодействие с формой, две вкладки и компоновку на мобильном экране. Ручной сценарий описан в CONFIGURATION.md.

# Проверка интерфейса 0.5

Дата: 3 октября 2026 года. Серверный контракт остаётся 0.4.0.

## Автоматические проверки 0.5

- 24 TypeScript-теста прошли: 16 прежних и 8 новых для архива. Проверены чтение без receivedAt, отсутствие команд записи, неверные идентификаторы и даты, немонотонная история, невозможные счётчики постов и времена событий, сетевые ошибки, расчёт метрик, нулевой выпуск, промежуточная/завершённая смена, конец графика и сохранение строгой проверки оперативного снимка.
- 34 Python-теста прошли без изменений серверной логики.
- Проверка TypeScript и production-сборка прошли.

## Работающий сервер

Новый клиент архива прочитал через реальные GET-запросы оба существующих сценария: завершённый с 361 годным изделием на 16:00 и промежуточный с 48 годными на 4241-й секунде смены. Нормализация receivedAt не применялась: архивные снимки приняты в исходном формате.

До и после чтения совпали runId, revision, state, forecast, controls и savedAt текущей линии. Команды, сбросы, запись и перезапуск сервера для этой проверки не выполнялись. Существующий сервер отдаёт сборку с разделом архива.

## Граница проверки 0.5

Браузерный инструмент снова не инициализировался: `failed to write kernel assets`, системный путь не найден. Поэтому открытие списка, скачивание браузером, компоновка на разных ширинах, навигация и диалог печати визуально не подтверждены. Это ограничение среды, а не успешная UI-проверка. Ручной сценарий — ARCHIVE.md.

# Проверка версии 0.4

Дата: 3 октября 2026 года.

## Автоматические проверки

- 34 Python-теста прошли: прежние 22 проверки и 12 новых для CSV, оценки прогнозов и хранения импортов.
- 16 TypeScript-тестов прошли: прежние 12 и 4 новые для HTTP-адаптера истории.
- TypeScript и production-сборка Vite прошли, в том числе после финальной правки текстов и выбора учебного файла.

Новые проверки: разделители, BOM и перестановка столбцов; неверные числа/режимы/структура; дубликаты времени; убывание счётчиков; неполная смена; лимиты размера/строк; независимый пересчёт метрик; отсутствие влияния будущих строк на ранние прогнозы; применение режима с его момента; редкие записи и повтор срезов; нулевой выпуск; отсутствие пригодных срезов; атомарное отклонение; сохранение после перезапуска; дедупликация; неизменность текущего двойника; план и Origin; целостность отчёта на клиенте.

Команды из корня проекта:

```powershell
npm.cmd test
.\.venv\Scripts\python.exe -m unittest discover -s backend -t . -v
npm.cmd run build
```

Starlette выдаёт предупреждение об устаревании транспорта httpx в TestClient; тесты проходят. Зависимости не менялись.

## Проверка работающего сервера

Версия API 0.4.0 запущена на 127.0.0.1:4173 с существующей базой. Перед запуском сделана резервная копия базы в рабочей папке проверки.

Через реальные HTTP-запросы проверены:

1. Импорт учебного CSV: 33 записи, 390 годных, 16 бракованных, MAE модели 134,67, MAE по темпу 21.
2. Повтор возвращает тот же importId; в базе одна запись импорта.
3. Неверный режим во второй строке даёт 422 с номером строки; импорт не сохраняется.
4. Отчёт читается по importId без изменений.
5. До и после импортов совпали runId, revision, state, forecast, controls и savedAt текущего двойника.
6. Корневая страница отдаёт production-сборку; документация OpenAPI сообщает версию 0.4.0.

## Визуальная проверка

Новый экран 0.4 визуально не проверен: браузерный инструмент дважды не смог инициализироваться с ошибкой записи служебных файлов среды (системный путь не найден), включая попытку после сброса инструмента. Другой способ управления браузером не применялся. Адаптивные стили предусмотрены, сборка проверена, но интерактивный выбор локального файла и компоновку 0.4 нужно подтвердить вручную. Ранее проверенные снимки 0.3 не являются доказательством проверки нового экрана.

Учебный отчёт уже сохранён через API и автоматически откроется в разделе «История». Для ручной проверки: выбрать пример, импортировать, обновить страницу, затем загрузить CSV с ошибкой и проверить сообщение с номером строки.

## Ограничения

Фактические данные АЛЛЮР не предоставлены. Модель не обучалась, параметры под файл не подгонялись. Оценка на одной синтетической смене демонстрирует процесс; промышленная точность и нагрузка не проверялись. Подробные допущения — HISTORY_IMPORT.md.
