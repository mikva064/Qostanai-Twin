# Пошаговый показ — интерфейс 0.11

Открыть: http://127.0.0.1:4173/#demo или пункт «Показ» в меню. Маршрут рассчитан примерно на две минуты живой демонстрации внутри выступления 9 октября. Реплики — подсказки ведущему; контрольные значения проверяются отдельно по данным сервера.

## Подготовка

«Начать учебный показ» создаёт новый сценарий с планом 410, подачей 65 с, циклами 48/52/58/50/55 с и буферами по 6 мест. Начальный срез — 08:45, пауза, 37 годных, прогноз 423. Текущий запуск сохраняется в архиве.

Если нормативы уже учебные, отправляется одна команда reset. Если отличаются, отправляется configure_line с явными учебными значениями; для неё сервер должен объявлять capability configure_line. Таким образом базовый показ работает и на API 0.4 с исходными параметрами. Серверный код остаётся версии 0.7.0; новых маршрутов и миграций нет.

Открытие раздела, переходы между экранами и закрытие подсказок сами не изменяют модель. Подсказки не запускают фоновый сценарий и не двигают модельные часы. Для каждого действия нужно нажать отдельную кнопку.

## Перед началом

Нажмите «Проверить готовность»: проверка читает состояние и не выполняет команды. Предупреждения о неподготовленном сценарии и отсутствии импортов на новом ноутбуке ожидаемы. Устраните ошибки, подготовьте учебный показ отдельной кнопкой и при необходимости импортируйте пример в «Истории». Результат проверки можно скачать в JSON. Если сайт не открывается, используйте `check.cmd`; инструкции — [RELEASE.md](RELEASE.md).

## Шесть шагов

| Шаг | Что сделать | Контроль |
|---|---|---|
| 1. Обзор | Показать линию; затем «Остановить P03» | До остановки 08:45, 37 годных, прогноз 423, пауза |
| 2. Остановка | «+15 модельных минут» | P03 остановлен; время переходит с 08:45 на 09:00 одной командой advance(900) |
| 3. Последствия | Показать поток и события, затем «Открыть сравнение P03» | 09:00, 39 годных, прогноз 39 при сохранении остановки |
| 4. Выбор решения | В разделе «Сценарии» нажать «Сравнить варианты», вернуться по ссылке «К подсказкам» | P03, ожидание 30 минут, 39/421/394, разница между сроками 27. После подтверждения доступно «Восстановить P03» |
| 5. Восстановление | «+5 модельных минут» | Перед шагом P03 нормальный, время 09:00, 39 годных, прогноз 421 |
| 6. История | «Показать проверку CSV» | После шага 09:05, 42 годных, прогноз 421. Прежнее сравнение помечено устаревшим |

В каждом разделе доступна плавающая ссылка возврата к подсказкам. Можно использовать обычные кнопки остановки и продвижения времени: если после ручного действия состояние точно совпало со следующим шагом остановки, последствий или финального продвижения, появится «Продолжить по состоянию линии». Она меняет только положение подсказки, без повторной команды серверу.

«Начать показ заново» создаёт ещё один учебный запуск с сохранением прежнего в архиве. «Закрыть подсказки» очищает локальный прогресс и оставляет линию в текущем состоянии. Перезагрузка страницы также очищает прогресс подсказок; серверное состояние при этом не сбрасывается. Смена скорости сама не влияет на контрольный поток на паузе, а включение воспроизведения нарушит точные контрольные времена.

## Что проверяется

Проверяется источник simulation в оболочке и состоянии, пауза, время, годный выпуск, прогноз, план, подача, очереди, незавершённые циклы, режимы, нормативы, счётчики обработки, работы и простоев всех постов. Эталон рассчитан отдельной проверенной моделью TypeScript и сверяется с реальными ответами Python API. Эталон не используется для подмены текущих данных на экране или работы без сервера.

Показ привязан к runId. Перед отправкой App проверяет, что полученные runId и revision ещё актуальны в этой вкладке; после ответа проверяет контрольное состояние. Это не серверная транзакционная блокировка от действий других вкладок: если данные изменились между запросами, результат должен пройти проверку, иначе шаг не засчитывается. При потере связи действия недоступны. При неподтверждённом ответе показывается ошибка; автоматической последовательности следующих команд нет. Повтор доставки отдельной команды использует обычную идемпотентность HttpDataSource.

Для восстановления требуется серверный отчёт сравнения того же runId и текущей revision, срез 09:00, P03, 30 минут и контрольные результаты. Принятие инцидента не меняет поток, но увеличивает revision: после него нужно пересчитать сравнение. Предыдущий расчёт другого запуска, времени, поста или ожидания не подтверждает шаг.

Проверки намеренно строгие. Если выполнялись другие команды, нормальные параметры не гарантируют совпадение незавершённых операций. В такой ситуации начните учебный показ заново; старый запуск останется доступен в архиве.

## Проверка и ограничения

50 TypeScript-тестов прошли, включая 7 проверок помощника; два новых интеграционных Python-теста проверили полный маршрут, контрольные числа, архивирование предыдущего запуска, восстановление инцидента, сохранение после перезапуска и возврат с нестандартных нормативов к учебным. Production-сборка прошла. Эталон API: docs/demo.reference.json; его можно заново получить командой `python -m scripts.generate_demo_reference` на временной базе.

Рабочая база не сбрасывалась для этих проверок. Браузерный инструмент недоступен из-за ошибки инициализации, поэтому клики, компоновку и удобство переходов нужно подтвердить на ноутбуке перед защитой. Проверьте прямую ссылку #demo, весь маршрут, возврат по плавающей ссылке, экран 390/1024/1440 px, короткое окно браузера со скроллом меню, потерю связи, обновление страницы и смену сценария во второй вкладке.

Резервный показ — существующая локальная презентация и сохранённые контрольные числа. Видео ещё не записано. Показ описывает условную модель участка; реального подключения, промышленной проверки и обученного ИИ пока нет.
