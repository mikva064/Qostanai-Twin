# Архив и отчёт сценария — интерфейс 0.5

Откройте `http://127.0.0.1:4173/#archive` или выберите «Архив» в меню. Достаточно обновить страницу на работающем сервере 0.4.0: новые маршруты и миграция базы не нужны.

## Поведение

- Список показывает до 50 последних записей `runs`, включая текущую. Источник — `GET /api/v1/runs`, подробности — `GET /api/v1/runs/{runId}`.
- При первом открытии выбран текущий сценарий, если он есть в списке. Можно выбрать любой другой; это только чтение сохранённого снимка.
- После сброса текущей модели список перечитывается. Уже выбранный сценарий остаётся открыт, пока доступен в списке.
- «Обновить архив» перечитывает список и выбранный отчёт. Если выбран текущий сценарий и его revision выросла, появляется предупреждение о старом срезе.
- Ошибка чтения не удаляет предыдущий отчёт; сообщение явно указывает, что показан ранее загруженный снимок.
- Результат более старого параллельного запроса игнорируется. Выбранный пункт, содержимое отчёта и экспорт меняются вместе после успешного чтения.
- В архиве нет команд восстановления или изменения старых сценариев. Оперативные команды остаются в разделе «Линия».
- Смена завершена только при `elapsedSec == shiftDurationSec`. Сброшенный раньше окончания сценарий показан как промежуточный срез.

Реальные даты отображаются по часовому поясу устройства. Производственные времена — часы модельной смены, начинающейся в 08:00. Эти шкалы подписаны отдельно. CSV-импорты остаются в разделе «История» и в список сценариев не входят.

## Формулы отчёта

| Показатель | Формула / смысл |
|---|---|
| Выполнение плана | `good / shiftPlan * 100`; для промежуточного среза — доля плана всей смены |
| Отклонение от плана | `good - shiftPlan`; итоговый вывод о выполнении показывается после завершения смены |
| Доля брака | `rejected / (good + rejected) * 100`; без выпуска — «Ещё нет выпуска» |
| Простои | Сумма `downtimeSec` всех постов; одновременные остановки суммируются |
| Пост с наибольшим простоем | Максимальный `downtimeSec`; при всех нулях лидер не назначается |
| Инциденты | События с severity warning/critical; информационные записи исключены из счётчика |
| Незакрытые инциденты | Из предыдущей строки те, у которых `resolvedAtSec == null` |
| Загрузка поста | `busySec / elapsedSec * 100`; на нулевом времени — прочерк |
| Изделия в потоке | Занятые места буферов + посты с `remainingWorkSec != null`, включая готовое изделие, ожидающее передачи |

График показывает накопленный факт только до сохранённого времени. Последняя точка берётся из текущих счётчиков снимка, даже если периодическая история ещё не записала этот момент. Прогноз не продолжается под видом факта. Пунктир — равномерный план на всю смену.

## Экспорт и печать

«Скачать JSON» сохраняет полный показанный снимок с runId, revision, savedAt, состоянием, событиями и прогнозом. Архивный API не содержит receivedAt; клиент не придумывает это поле. Экспорт старого среза остаётся старым срезом, даже если оперативная линия продвинулась.

«Печать отчёта» использует стандартный диалог браузера. Можно выбрать сохранение в PDF. Печатные стили оставляют только отчёт выбранного сценария, повторяют заголовки таблиц и сохраняют указание демонстрационных данных. Для печати нужна ранее успешная загрузка отчёта. Открытие диалога и разбиение страниц ещё не подтверждены визуальной проверкой.

## Ручной прогон перед защитой

1. Открыть прямую ссылку `#archive`, проверить выбранный пункт меню и видимость раздела. Проверить переход назад к `#history` и вперёд средствами браузера.
2. Выбрать завершённый сценарий: заголовок «Итоги смены», время 16:00, факт и итоговое отклонение от плана.
3. Выбрать промежуточный сценарий: заголовок со временем среза, график заканчивается раньше 16:00.
4. Проверить таблицу постов и журнал событий. Счётчик инцидентов не включает запись «Смена запущена».
5. Скачать JSON и сопоставить runId, revision, good с показанным отчётом.
6. Открыть печать и просмотреть все страницы: только выбранный отчёт, без других разделов приложения. Отменить печать и проверить обычный экран.
7. В текущем сценарии продвинуть время на +5 минут, если смена ещё не завершена. Старый отчёт должен получить предупреждение; после «Обновить архив» данные обновляются.
8. При желании начать новый сценарий через штатный сброс и снова открыть прежний в архиве. Сброс создаёт новую запись; для проверки только чтения этот шаг не требуется.

Эти действия с интерфейсом не отмечены как выполненные автоматически. Данные существующей базы проверены напрямую через HTTP без выполнения команд.
